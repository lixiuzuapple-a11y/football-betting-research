# EV-Lab 第一阶段：统一官方赔率数据工厂（可执行规格）

## 目标与边界

把原有多个 `TASK0017/0024/0025` 有界官方采集批次并入同一个**新的**研究数据库；所有原始采集记录保持只读，且研究库不修改任何原始数据。

此入口**只**产出赛前候选报价事件、来源信息、资格拒绝计数与比赛主客ID索引：
不导入赛后赛果、不推断赔率实际成交、不判断胜平负、不计算收益、不下注。

## 与历史工程的关系

直接复用既有的：
- `task0017_official_only.py` 的 SQLite + gzip + SHA256 原始记录约定。
- `task0028_timeline_gate.py` 的官方五市场、赔率向量与提供方时间戳。
- `task0029_quote_candidates.py` 的 Selling/状态标记、同时间矛盾、回滚与重复价格状态机。
- 不改动历史运行目录/数据库，也不把任何三方原始来源提交 GitHub。

本工具在**不同采集批次之间全局按实际接收UTC时间排序**，不按目录顺序；读取压缩文件时逐份检查SHA256，按源数据库标记的match_count核对实际结构，并拒绝伪造、不一致和不安全路径。

## 运行

```bash
python -m tools.phase1_data_factory \
  --root /path/to/task0024-official-20261010 \
  --root /path/to/task0025-official-20261015 \
  --out-db /new/off-host-root/candidate_quotes.sqlite3 \
  --out-summary /new/off-host-root/quality_summary.json
```

- 默认只接受提供方报价更新时间距本机收到数据 `<=6h` 的报价，作为审慎研究门槛（并非官方成交资格）。
- `--max-quote-age-hours` 可以显示改变这个研究门槛；**不能**靠调该参数优化已知赛果。
- `--max-captures N` 可用于有限诊断，结果有 `partial_scan=true`，不可以冒充完成的全集。
- `--out-db` 和 `--out-summary` 必须是不存在的新文件，数据库不得位于任一源目录下。
- 请在新存储区保留输出数据库和摘要；本仓库不会提交大量或可能受限的第三方原始字节。

## 产出数据约定

- `source_captures`：每次官方采集的源root、capture ID、接收时刻、状态、原始SHA256、比赛数。
- `fixtures`：不含赛果的球队ID、原始比赛日期及开球UTC；对不相容的同 matchId 信息按安全规则拒绝。
- `quote_candidates`：有效的初始或后来更新报价；包含市场、实际接收UTC、提供方更新UTC、来源哈希、matchId、状态机事件类别和赔率向量JSON。
- `quality_summary.json`：源运行路径、原始验证数量、赛前观察数量、各市场拒绝原因和候选报价事件数；展示口径与统计对象一一对应。

**必须注意：** `quote_candidates` 记录的是观测到的、满足保守研究筛选的赔率变化，并不是盘口逐笔成交簿。没有成交价、成交量、跨平台同一时点盘口，也没有可计算的真实CLV和ROI。

## 后续生产阶段不得跳过的门槛

1. 独立开启**新的官方采集 root**，限制最短抓取间隔、运行最长时间、失败次数、磁盘空间；独立定时监控必须能验证 freshness、SQLite、HTTP/JSON 和终止原因。
2. 持续运行至少多个自然日，验证自动化、恢复策略、失败告警及可追溯采集窗口；旧的七天任务结束不代表任何新服务已就绪。
3. 为**独立预测器**引入足量的赛前可用历史训练资料和合法来源，然后事前封存模型输出。不得用官方赔率冒充独立预测。
4. 只有在源-赛前特征-模型概率-市场报价-赛果完全隔离后，才能启动盲评和纸面 BUY/PASS 实验。
