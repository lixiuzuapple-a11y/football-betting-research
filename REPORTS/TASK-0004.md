## 3. Phase A — answers to the five mandated questions

### A1. Is there already a true timestamped sharp/reference quote source?

**No.**

- Repository: `available_sources() -> ()`; the loader is an explicit stub that is
  type-level incapable of returning rows (`docs/data-policy.md` §5 makes this a
  design rule, not an oversight).
- Legacy: every external market dataset in the archive is either
  football-data.co.uk (daily CSV, opening/closing columns) or BetExplorer/oddsportal
  HTML (opening/closing labels). `research/P0_EVIDENCE_RECONSTRUCTION_20260923.md`
  §4.1 states this explicitly for `e54_join.csv` and `e56_had_join.csv`:
  "**does not contain an external-market observation timestamp**".
- No legacy script anywhere fetches a bookmaker odds-movement page.

### A2. Timestamp semantics available

Three distinct kinds exist in the legacy assets, and they are **not** interchangeable:

| Kind | Example field | Meaning | Where |
|---|---|---|---|
| Our observation time | `snapshot_time`, `collect_time` | when the collector ran | `sporttery_collector.py`, `jc_ts_probe.py`, `e1_probe_sources.py` |
| Provider-declared update time | `updateDate` + `updateTime` | the Sporttery pool's own declared odds-update instant | Sporttery API, all collector outputs |
| Opening/closing **label** | `PSH/PSD/PSA` vs `PSCH/PSCD/PSCA` | **not a timestamp at all** — a position label | football-data.co.uk, BetExplorer |

The Sporttery side therefore satisfies the two-clock requirement (`observed_at` +
provider-update-time). The **external** side, in the entire archive, only ever
reaches the third kind — a label. That is exactly the gap TASK-0004 was commissioned
to close.

### A3. Which markets are available

- Sporttery (official API): `had`, `hhad`, `crs`, `ttg`, `hafu` — five pools, one call each.
- External (legacy, football-data.co.uk): 1X2 only for explicit Pinnacle; plus
  `AvgAHH/AvgAHA`, `Avg>2.5/Avg<2.5`, `B365*`, `Max*` — a **bookmaker-set average and a
  maximum**, not a named sharp book, and only as opening/closing.
- Legacy BetExplorer scrapes: 1X2 league tables (opening/closing).

### A4. Can an external record map one-to-one to Sporttery event / market / selection / line?

**Event level: historically yes, with manual mapping work. Contract level + same-time: no.**

- Legacy joins exist (`e54_join.csv` 4,596 matched rows; `e56_had_join.csv` 3,430 rows)
  and required dedicated team-name mapping scripts (`build_team_name_map.py`,
  `build_be_team_map.py`, `team_map_index.py`, `add_j1_sau_map.py`, `add_k1_map.py`).
  The joins carry Sporttery match identity plus Pinnacle **opening/closing** fields.
- No archived join contains line/selection equivalence with an external observation
  timestamp, so a same-time, same-contract mapping is **not established**.
  `EDGE_EXHAUSTION_MATRIX` C09 keeps settlement/line-equivalence mapping as
  "SURVIVES as CORE VALIDATION — never 'closed'".

### A5. Does an acceptable source require new account / paid plan / token / proxy / browser automation / ToS-sensitive scrape?

For every source already in the archive: **no credentials required**
(Sporttery official API, football-data.co.uk, BetExplorer, okooo, 500.com are all
public, unauthenticated). But none of them is a sharp/reference quote stream.

For every plausible **sharp** source identified, at least one of the stop-conditions
is triggered — see §5.

## 5. Smoke capture result

**Not attempted. Outcome: BLOCKED.**

Both sides of the required synchronized pair fail independently:

### Blocker B1 — the Sporttery side itself is unreachable by a non-browser HTTP client

`getMatchCalculatorV1.qry` **and** the Sporttery homepage `https://www.sporttery.cn/`
both return **HTTP 567** with the identical 7,351/7,352-byte HTML interstitial.
Reproduced in **six** independent attempts:

| Attempt | Configuration | Result |
|---|---|---|
| 1 | env proxy `127.0.0.1:15604` + `Referer: https://www.sporttery.cn/` | 567 |
| 2 | direct (proxy bypassed) + `Referer` | 567 |
| 3 | direct (proxy bypassed), **no** `Referer` | 567 |
| 4 | direct + browser-like headers (`Origin`, `Sec-Fetch-*`, JSON `Accept`) | 567 |
| 5 | retry after 8 s | 567 |
| 6 | retry after a further 8 s | 567 |

The response body (`probe/evidence/sporttery_567_challenge.html`, preserved locally
outside the repo) contains a `<script>` element and a `navigator` reference — i.e. it
is a JS-driven challenge page, not a plain error document.

Because the result is identical with the sandbox proxy, without any proxy, with and
without `Referer`, and with browser-like Fetch Metadata headers, the block is **not**
explained by proxy selection or request headers.

- Root cause: **UNKNOWN.** Two explanations remain unresolved and I did not attempt
  to discriminate them, because doing so would cross the task's stop-line:
  (a) Sporttery now serves a JS challenge to all non-browser clients;
  (b) a network/IP-reputation block specific to this machine's egress.
- Resolving it would require driving a real browser session through the challenge.
  That is a deliberate defeat of a bot-detection control, i.e. exactly the
  "bypassing access controls" / "ToS-sensitive scrape" condition that this task
  orders me to **stop and report before** attempting. I did not attempt it.

### Blocker B2 — the sharp side has no free, unauthenticated, timestamped option

Per §4: the sharp/exchange candidates are Cloudflare-blocked (Pinnacle guest, 403),
geo/legally blocked and account-gated (Pinnacle official, 451), or credential-gated
(Betfair 403, The Odds API 401). The only reachable free sources are soft-book
aggregators whose odds are published as opening/closing labels with no quote-change
timestamps (BetExplorer: 0 ISO-like timestamps measured), or Chinese aggregators that
mirror Sporttery rather than an external sharp book.

### Consequence

A synchronized dual-market capture **cannot be produced inside the allowed envelope**
("without Owner supplying new credentials or spending money", bounded public
unauthenticated probes only). Per the task text this is a valid outcome:

> If no acceptable source is available: STOP. This is a valid outcome.

and per `research/P0_EVIDENCE_RECONSTRUCTION_20260923.md` §6:

> If no suitable source is accessible without new credentials/cost, the correct
> deliverable is a blocker report, not fabricated data.

**Nothing was substituted.** No Pinnacle closing odds, no daily opening prices, no
soft-book average relabelled as sharp, no model probability, and no invented or
