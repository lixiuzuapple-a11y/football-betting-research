# TASK0063｜真实官方赛程 × The Odds API 未来候选赛事身份预检

日期：2026-11-10（北京时间），只处理 EV-Lab 足球主线。

## 命题

目前瓶颈究竟是球队名称、官方待售赛程的联赛范围，还是严格的赛前原始赔率证据？从现有连续官方采集器取**一个真实、可回溯 SHA 的赛程快照**，与已有的 The Odds API 免费法甲快照进行只读、零额外请求的预检。

## 纪律

1. 仍使用 TASK0045 采集器和 TASK0043/TASK0059 的正式 14 联赛门禁，沿用 TASK0060 的 143 支已批准官方↔HF 球队身份。不扩大联赛、不修改冻结预测或现有生产任务。
2. 采用 TASK0061 的候选与正式事件身份严格隔离：HF 源名称与 The Odds API 名称完全相同，只能产生**待核验候选**；必须另外获得官方比赛 ID、双方身份、开球及报价收件/Git 时序的独立证据，才能进入同时点验证。
3. 原始官方 gzip 与原始 API JSON 仅在本地 E 盘 Git 忽略目录；Git 仅提交无密钥的摘要、名单、结论与独立 QA。
4. 不付费、不加新定时器、不消耗新赔率额度、不生成 BUY/PASS 或正 EV 结论。

## 通过标准

可精确报告官方总数、已批准联赛/身份资格、国际赔率未来候选数量、正式事件 ID 是否可关联，并用第二方法重算哈希及名单。即便跨源正式关联为 0，也必须明确给出可执行的下一步触发条件，不以放宽门禁伪造正结果。
