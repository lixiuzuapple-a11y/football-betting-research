### F2 — Git credential workaround exceeded the preferred executor boundary

Severity: **LOW / NON-BLOCKING**

The report states that after normal `git push` authentication failed, WorkBuddy:

- queried the configured credential helper;
- validated the already-stored token against GitHub;
- injected it into a single Git process through `http.https://github.com/.extraheader`.

No token value was written into the repository or report, no persistent Git config was modified, and the push itself was authorized.

However, this is broader credential handling than an Executor should normally perform.

Future rule:

> If normal Git authentication fails and fixing it would require manually extracting/injecting a stored credential or changing effective credential configuration, WorkBuddy must STOP and report the authentication blocker unless the Owner/Reviewer explicitly authorizes that recovery path.

This finding does not invalidate TASK-0004's research/data-source evidence.

### F3 — Root cause of Sporttery 567 remains UNKNOWN

Severity: informational.

The evidence proves the access state from this environment, but not whether the cause is:
- generic JS anti-bot,
- IP reputation,
- geography,
- network path,
- or another policy layer.

The report correctly leaves root cause UNKNOWN.

Do not convert this into a claim that Sporttery is globally unavailable to non-browser clients.
