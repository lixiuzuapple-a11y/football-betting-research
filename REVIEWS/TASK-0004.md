### BLOCKING F1 — per-pool provider timestamps are collapsed

Severity: **HIGH / BLOCKING**

The saved official raw payload exposes different timestamps for different pools. Example `周三003 西雅图 vs 盐湖城`:

- HAD update = **2026-09-23 18:51:22**
- HHAD update = **2026-09-23 18:51:31**
- TTG update = **2026-09-23 21:50:41**

The committed parser currently stores one `SportteryQuote.odds_updated_at` as the **maximum** of the HAD/HHAD/TTG timestamps.

That means the HAD price can be represented with the TTG timestamp. In this example HAD would appear to have changed at 21:50:41 although its actual provider update is 18:51:22.

For D01-B this can move the apparent stale interval by hours. It violates the task's market-specific timestamp discipline.

Required fix:

- preserve provider update time **per pool**;
- do not collapse HAD / HHAD / TTG into one market timestamp;
- expose explicit per-pool fields or an immutable mapping keyed by pool code;
- absent pool timestamps remain `None`;
- add a regression test proving the three unequal timestamps above survive separately.

An optional aggregate such as `latest_pool_updated_at` is acceptable only if its aggregate semantics are explicit and it cannot be confused with a particular market's update time.

### BLOCKING F2 — required per-pool executability fields are omitted

Severity: **HIGH / BLOCKING**

TASK-0004 requires the Sporttery side to retain single/all-up availability and pool status.

The saved raw payload already contains these facts in `poolList`, including:

- `poolCode`

- add regression coverage showing different pools on one match can have different single-bet eligibility.
